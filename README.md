# Four Wheel Steer

A 2D top-down car game where you steer the **front and rear wheels independently**.
Steer both axles the same way and the car **crab-walks** sideways; steer them opposite
and it does a **tight pivot**. Race a looped **circuit**: hit the checkpoint gates in order
and cross the start/finish line to complete a lap — **3 laps** per race, chasing your **best
lap**. **Stay off the walls: the third wall hit in a race is game over.** The handling is a
sim-ish slip-angle model (see Tuning).

Race through **5 levels** of rising difficulty, beating target times for **gold / silver /
bronze medals** — finishing a level unlocks the next. Progress (best times, medals) is saved
between sessions.

Built with **Godot 4** (sound effects are generated by `tools/generate_sfx.py`; no other
external assets).

## Look & feel (design system)

The UI is built in code and styled from a small **design system** in `ui/`: a Godot `Theme`
(`four_wheel_steer_theme.tres`, set as the project-wide GUI default) plus `Palette.gd` color
tokens (autoloaded as `Palette`) for the procedural bits — track, cars, HUD arrow, gates. The
palette is a dark-navy UI with a **gold** hero accent and **blue** player color: gold primary
buttons, blue secondary, ghost outlines, red for Quit; a green road on a navy field; a blue car
with a gold nose. The display/UI/HUD face is **Chakra Petch** (Bold) and body copy is **Barlow**
(Regular) — both are bundled in `ui/fonts/` (Open Font License) and wired into the theme (Barlow
applies via the `LabelBody` type variation). The source design system lives in
`Four Wheel Steer — Design System/` (excluded from the Godot import via `.gdignore`).

Depth comes from `ui/hud_style.gd` (`HudStyle`): translucent "glass" panels with a hairline rim
and soft shadow for the race HUD, glow and vignette textures, the shared grid-and-glow backdrop
behind the menus, and `feather()`, which smooths the edge of solid shapes. The road is a mesh of
ribbons shaded by vertex colour (a soft glow outside the walls, darker road beside them, a lighter
crown), sitting on a faint grid. This renderer (GL Compatibility) has no 2D multisampling, so
smooth edges come from anti-aliased lines and circles, not a project setting. Screenshots are in
`docs/screenshots/`.

## Run it on desktop

1. Download Godot 4.x (Standard, not .NET) from <https://godotengine.org/download> — it's a
   single `.exe`, no installer. Unzip and run it.
2. In the Project Manager: **Import** → browse to this `FourWheelSteer` folder → pick
   `project.godot` → **Import & Edit**.
3. Press **F5** (or the ▶ button). You'll land on the **main menu** → **Play** → pick a level.

### Controls (desktop)

| Key | Action |
|-----|--------|
| **W / S** | throttle / brake-reverse |
| **A / D** | steer **front** wheels |
| **← / →** | steer **rear** wheels |
| **Shift** *(or **C**)* | boost (burns the boost meter) |
| **Space** | handbrake (drift) |
| **Esc / P** | pause (Resume / Restart / Menu) |

Restart and "next level" are on the pause and results screens. During a race the same list sits
under the top row as a strip of **key caps** (thumb-pad icons on touch). It is built by
`HudStyle.controls_legend()` in `ui/hud_style.gd`. **How to Play** is pictures, not sentences: four
tiles (FRONT, REAR, SPIN TURN, SIDEWAYS), each a little car with its wheels turned, the keys or
pads that do it and its name, then "3 WALL HITS = OUT" and the rest of the controls as key caps.

### Controls (touch)

Two thumb pads appear at the bottom of the screen on a phone, in a browser that reports a
touchscreen, on any device the moment you touch the screen, or when you click a phone-shaped window
with the mouse (a desktop browser's mobile view; the mouse then drags one pad at a time). Pressing
a key hides them again. A pad re-centres under your thumb wherever it lands in its half of the
lower screen, so every gesture is relative to where you touched.

| Gesture | Action |
|---------|--------|
| **Left pad** left / right | steer **front** wheels |
| **Right pad** left / right | steer **rear** wheels |
| Push **either** pad up | accelerate (further = more throttle) |
| Push **both** pads fully up | boost |
| Pull **one** pad down | handbrake (drift); keep the other up for a power slide |
| Pull **both** pads down | brake, then reverse |
| **II** button (top right) | pause |

The pads are true multi-touch (`scripts/touch_controls.gd`), so both axles can be steered while
accelerating. The thresholds are constants at the top of that script.

### Screen sizes

The UI lays itself out for the window's shape (`scripts/layout.gd`, the `Layout` autoload): a wide
window gets the desktop arrangement on a 1280x720 logical canvas, a tall one (a phone, or a narrow
desktop window) gets phone-sized menus and HUD on a 430x760 logical canvas, and it switches live if
the window is resized across the two.

### Try the signature moves

- **Crab walk:** hold **D** and **→** together (front + rear both right) → the car slides
  diagonally without spinning.
- **Tight pivot:** hold **D** and **←** (front right, rear left) → it rotates in a very
  small circle.
- **Handbrake slide:** carry speed into a corner and tap **Space** → the rear breaks loose for
  a drift; overcook the entry and it'll spin. The handling is **sim-ish** — momentum, weight,
  and grip you can overdrive, though without the handbrake the car stays planted and goes where
  its wheels point. Drifts lay **skid marks** and kick up **dust**; wall hits **shake**
  the screen.
- **Boost:** hold **Shift** (or push both thumb pads fully up) on a straight to burst past your normal top
  speed; it drains the boost meter, refills when you let off, and the camera pulls out as you surge.

## Track, levels & progression

- **Data-driven circuits** (road with walls on both edges): a closed centerline + road width in
  `scripts/game_data.gd` (`TRACK_1`..`TRACK_5`) is turned into the road, walls and gates by
  `scripts/track_builder.gd`. Preview/iterate a shape without the editor via
  `python tools/preview_track.py <id>` (`t1`..`t5`; writes `track_preview.png`), or
  `python tools/preview_track.py all` for every level side by side (writes
  `docs/tracks_overview.png`).
- **The waypoints are a guide, not the exact road.** The builder runs a centripetal Catmull-Rom
  spline through them, spaces the points 10 px apart, then eases any bend tighter than half the
  road width + 24 px. That guarantees the inside edge of the road never folds over itself, however
  close together two waypoints are. `godot --headless --path . -s tests/track_test.gd` checks it
  on every track.
- **5 levels**, each a **3-lap race**, unlocked in order (a level opens once the one before it
  has been finished). Difficulty rises level by level: the road narrows and the top speed climbs
  from Level 3 on.
- **Inside a Reddit post it is one circuit a day.** Play opens **Today's Circuit**: that day's
  level drawn as a diagram (`scripts/track_diagram.gd`: the road at true proportions, the
  chequered start line, a gold arrow for the direction), its medal times and a **DRIVE** button.
  No other level is offered there, and the results card has no "Next".

  | Level | Road | Top speed | Character |
  |---|---|---|---|
  | 1 | 88 px | 620 | medium width, flowing |
  | 2 | 75 px | 600 | tight and twisty |
  | 3 | 72 px | 665 | deeper esses on both sides |
  | 4 | 68 px | 700 | esses along the top and bottom, a tight two-hairpin switchback |
  | 5 | 64 px | 725 | three hairpins (a narrow inlet, a double switchback) plus esses on three sides |
  - No level has obstacles. The cone / wall / ramp code is still in `track_builder.gd`,
    `cone.gd` and `ramp.gd` (a track dict may carry
    `"obstacles": [{type:"cone"|"wall"|"ramp", t, offset, …}]`), but nothing uses it.
  - Add a track with a `TRACK_n` dict + a `LEVELS` entry in `game_data.gd`. Give the entry a new,
    never-used `id`: saved times and the leaderboard are keyed by it, so levels can be reordered
    without times landing on the wrong track.
- **Three strikes.** Every new touch of a wall is counted across the whole race (one scrape or
  bounce is one touch; `car.gd` decides, see `WALL_*` constants). The HUD shows three **WALL
  HITS** pips. Hits 1 and 2 flash the screen edge red with a warning; hit 3 is **GAME OVER**:
  nothing is saved and the next level stays locked. The limit is `MAX_WALL_TOUCHES` in `game.gd`.
- A **3-2-1-GO** countdown starts each race; the HUD shows **Lap x/3**, a lap timer, total time,
  **best lap** (flashes on a new best), a **radial speedometer** gauge, a **boost meter**, a live
  **+/- split delta** vs your best lap (green = ahead, red = behind), and an **arrow to the next gate** (handy since
  the camera rotates with the car). The camera is zoomed in, so a **mini map** (top right) shows
  the whole circuit: north stays up, your car is the blue arrow, the next gate pulses gold, and the
  white bar is the start/finish line.
- On finish you get a **medal** by total time; **best time + best lap** are saved, and **Next**
  appears if there is another level. The only way to fail is the third wall hit; retry freely.
  Progress is in `user://save.json`.

## Compete with friends: the online leaderboard

Instead of racing at the same time, everyone races the time-trial **separately** and competes on a
**shared online leaderboard**. Open **Leaderboard** from the main menu; finishing a race uploads
your time automatically.

**Inside a Reddit post** the board comes from the game's own Devvit server (no setup) and players
are their Reddit accounts:

- **OVERALL** (the first board): each player's best times on **all 5 levels added up, lowest
  total on top**. A player appears once they have a time on every level; until then the screen
  says how many they have.
- **One board per level**: best time ever on that level.
- **TODAY** (the second board): fastest on the day's circuit.
- **Daily Circuit**: each day one level is featured (they take turns). Its board and the streak
  shown on the post count only that level. The post's **Leaderboard** button opens the game
  straight onto the boards.
- **The results card** after a finish shows your place on today's board ("#12 OF 340 TODAY"), a
  NEW BEST chip, your streak in days, and a countdown to the next circuit. Its gold
  **Leaderboard** button opens the TODAY board.

**Everywhere else** (desktop, Android) it uses **[Appwrite](https://appwrite.io)**, one board per
level, with a name you type on the screen. It runs over plain HTTPS — no
account or login needed in-game. You set the backend up **once**, then everyone who runs the build with
your IDs shares one board.

**One-time Appwrite setup (host/owner):**
1. In the **Appwrite console** create a **project** → note its **Project ID** and **API endpoint**
   (e.g. `https://nyc.cloud.appwrite.io/v1`).
2. **Databases → create a database** → note the **Database ID**.
3. Create a **collection** named `scores` → note the **Collection ID**. Add attributes:
   `name` (string, size 24), `level` (integer), `time_ms` (integer).
4. **Collection → Settings → Permissions:** add role **Any** with **Create** + **Read**.
5. Paste the four IDs into the constants at the top of **`scripts/leaderboard.gd`**
   (`ENDPOINT` / `PROJECT_ID` / `DATABASE_ID` / `COLLECTION_ID`) and re-build.

Until those are filled in, the Leaderboard screen just shows a "not set up yet" note — the rest of the
game is unaffected. (Scores are submitted by the client, so this is a friendly board, not a
cheat-proof one.)

> The real-time **multiplayer** experiment (host/join, car-to-car bumping) is still in the codebase
> but disabled — it's no longer on the menu. The networking lives in `scripts/net.gd` / `scenes/Lobby.tscn`
> if you want to revive it.

## Run it on Android

The project is already configured for mobile: **portrait** orientation, the
`gl_compatibility` renderer (widest device support), phone-sized layouts, and the on-screen
thumb pads (see "Controls (touch)").
(Desktop opens maximized/landscape.)
Building an APK is a one-time tooling setup:

1. **Install the Android build template:** in Godot, `Project → Install Android Build
   Template…`
2. **Install the SDK + JDK:** the simplest route is to install **Android Studio** (it
   bundles the Android SDK) and **JDK 17**. Then in Godot: `Editor → Editor Settings →
   Export → Android` and set the **Android SDK Path** and **Java SDK Path** (or **Debug
   Keystore** — Godot can generate a debug keystore for you from the Export window).
3. **Export:** `Project → Export…` → the **Android** preset is already here →
   **Export Project** to `build/FourWheelSteer.apk`.
   - Or one-click deploy: plug in a phone with USB debugging on and press the little
     Android/▶ "remote deploy" button in the top-right of the editor.
4. **Command line** (after the above is configured):
   ```
   godot --headless --path . --export-debug "Android" build/FourWheelSteer.apk
   adb install -r build/FourWheelSteer.apk
   ```

> The app id is `com.saini.fourwheelsteer` (change it in `export_presets.cfg` or the
> Export dialog if you like).

## Share it for others to test

Easiest (no install, works on desktop + mobile browsers): **Web export → itch.io.**

1. In Godot: `Project → Export…`. If it warns about missing templates, click **Manage Export
   Templates → Download and Install**.
2. Select the **Web** preset → **Export Project** → save into `build/web/` as `index.html`.
3. Zip the **contents** of `build/web/` and upload to **itch.io** as an HTML5 game (tick *"This
   file will be played in the browser"*). Share the page link. (GitHub Pages / Netlify also work —
   just host the `build/web` folder.)

Other options (presets already in `export_presets.cfg`):
- **Windows:** export the **Windows Desktop** preset → `build/windows/FourWheelSteer.exe` (PCK
  embedded) → zip and share. Windows-only, requires a download.
- **Android:** the **Android** preset builds an APK (needs the Android SDK/JDK set up first, above);
  testers enable "install unknown apps" to sideload it.

## Run it on Reddit (Devvit Web)

`reddit/` is a [Devvit Web](https://developers.reddit.com/docs/capabilities/devvit-web/devvit_web_overview)
app that runs the **Web export of this project inside a Reddit post**, as a daily game ("Daily
Circuit": one track per UTC day, a per-day leaderboard and a play streak). It needs Node 22+ and
Godot 4.7 with the Web export templates.

```bash
cd reddit
npm install
npm run export:godot   # headless Godot "Web" export -> reddit/public/ (index.js/.wasm/.pck)
npm run build          # bundle the web view scripts + the Devvit server
npm test               # daily rules: best time, rank, streak
npm run local          # http://localhost:5180/splash.html, strict CSP + fake API, no Reddit needed
npm run dev            # devvit playtest: uploads and installs to your test subreddit
```

The touch controls have their own headless test, run from the project root:
`godot --headless --fixed-fps 60 --path . -s tests/touch_test.gd` (37 checks: steering, throttle,
boost, drift, brake, pause, the portrait/landscape switch, and the mouse driving the pads in a
phone-shaped window). The track geometry has one too:
`godot --headless --path . -s tests/track_test.gd` (no folded edges, no over-tight bends, the
road never running into itself, and gates and start slot on the road, for all 5 levels and the
multiplayer track). And the rules:
`godot --headless --fixed-fps 60 --path . -s tests/rules_test.gd` (five levels, no obstacles,
and the three-wall-hits rule: what counts as one hit, the warnings, and game over).

- **Why a custom loader:** Reddit's web view blocks inline `<script>`/`<style>`, which Godot's
  default `index.html` uses. `tools/export-godot.mjs` discards that page and keeps only the engine
  files plus the engine settings (`public/godot-config.js`); `public/game.html` +
  `src/client/game.ts` boot the engine instead. The Web preset must keep **thread support off**.
- **Re-run `npm run export:godot` after any change to the Godot project** — the web view ships
  the last export, not the live project.
- **Post flow:** the post shows `splash.html` inline (tiny, instant); tapping Drive opens
  `game.html` expanded, and only then is the ~38 MB engine downloaded.
- **Server** (`src/server`): `GET /api/init`, `POST /api/run`, `GET /api/leaderboard`, a daily cron
  (00:00 UTC) and a moderator menu item that create the day's post. Data lives in Devvit's redis.
- **Game ↔ server bridge:** `game.ts` exposes `window.FWS` (`init` JSON + `request(...)`); the Godot
  side reaches it with `JavaScriptBridge.get_interface("FWS")`. *The game does not use it yet* — it
  still boots into the normal menu.

## Tuning

The handling is a **sim-ish slip-angle (bicycle) model** in `scripts/car.gd`. Select the
**Car** node in `scenes/Car.tscn` and tune the exported values in the Inspector:

- **Grip / slide:** `grip_accel` (cornering grip before the tyre slides),
  `cornering_stiffness_front` / `cornering_stiffness_rear` (lower rear = more oversteer),
  `traction` (how fast a sideways slide is pulled back toward where the wheels point; 0 = slides
  freely), `handbrake_traction` (the share of that kept on the handbrake),
  `handbrake_rear_grip` (how far the handbrake frees the rear).
- **Weight:** `yaw_inertia` (higher = heavier, slower rotation), `rolling_resistance` / `drag`
  (coast-down).
- **Steering:** `steer_sensitivity`, `high_speed_lock` (lock retained at top speed),
  `max_steer_aligned_deg` / `max_steer_opposed_deg`.
- **Camera feel:** the camera dollies **out** as you speed up (more road visible) and back in when
  slow — tune with `camera_zoom_rest`, `camera_zoom_at_top` (fraction of rest zoom held at top
  speed), and `camera_zoom_lerp` (how fast it eases). Braking/handbraking lights the **rear brake
  lights**.
- **Boost:** held boost adds forward thrust and a higher speed ceiling, burning a meter that refills
  when idle — `boost_accel`, `boost_speed_mult` (ceiling = this × top speed), `boost_duration`,
  `boost_recharge_rate`, `boost_min_to_fire`, `boost_decel` (overspeed bleed-off), `boost_zoom_out`.

Speed bleeds in corners naturally (no artificial cap). Per-level top speed and acceleration come
from the `LEVELS` table in `scripts/game_data.gd` (they override the Car's defaults at the start
of each race). Regenerate the sound effects any time with `python tools/generate_sfx.py`.
